# SPEC — SEM Nanostructure Classifier (working name: `sem-nanostructure-classifier`)

Status: ACCEPTED (2026-10-05). Changes after acceptance are listed in section 11.

## 1. Goal

Train an image classifier for scanning-electron-microscopy (SEM) images of nanostructures and, more importantly, **measure honestly how much of its reported accuracy is real**. The project's central question:

> How much of the accuracy of SEM image classification is inflated by near-duplicate leakage and by shortcuts (e.g. the instrument info bar), and what does a leakage-free evaluation look like?

Non-goals: clinical or industrial claims; state-of-the-art benchmark chasing; training large models from scratch.

## 2. Data

- **Source (only):** NFFA-EUROPE "100% SEM Dataset", CNR-IOM Trieste (Aversa, Modarres, Cozzini, Ciancio). DOI `10.23728/b2share.80df8606fcdb4b2bae1656f0dc6db8ba`, B2SHARE.
- 21,169 images, 10 classes: Biological, Fibres, Films & Coated Surfaces, MEMS devices & electrodes, Nanowires, Particles, Patterned surfaces, Porous Sponge, Powder, Tips. Total about 13.6 GB (10 tar archives).
- **License:** CC-BY (attribution required; cited in README and model card). Third-party mirrors (e.g. Hugging Face copies) are NOT used: their license is unclear.
- **Known property:** the dataset description states that no scientific metadata (instrument, magnification, sample ID) is attached to the images. Therefore a "split by source" is not possible directly; groups are derived from image similarity (section 4).
- Labels were validated by nanoscientists, but classes overlap conceptually (e.g. Powder vs Particles); label noise is expected and will be reported, not hidden.

## 3. Data security and integrity (hard requirements)

1. Public, open-licensed data only. No personal, client, recruitment-task or employer data.
2. No secrets in the repo: no `.env`, no cloud keys. Training runs on free Kaggle/Colab GPUs, so no cloud credentials are needed. `.gitignore` is created BEFORE the first commit (covers `.env`, data, checkpoints, caches).
3. Raw data is not committed. The download is verified against the publisher's MD5 sums; the SHA-256 of every archive is recorded in the repo (`checksums/`), so any later run can re-verify integrity.
4. **Leakage rules:** (a) splits are created once, deterministically (fixed seed), and saved as `splits.json`; (b) near-duplicates never cross splits; (c) the test set is evaluated exactly once, at the end, and all tuning uses validation only; (d) preprocessing statistics are fit on train only.
5. Reproducibility: pinned dependencies, fixed seeds, 3 seeds per experiment, environment recorded in the report.
6. A public demo (if built) has an input size limit and a rate limit, and stores no uploads.
7. The repository contains no traces of AI tooling (no co-author trailers, no mentions in README/SPEC).

## 4. Experiments

| ID | Question | Method |
|---|---|---|
| E0 | What is in the data? | Class counts and imbalance, image sizes, near-duplicate detection (perceptual hash + embedding similarity), detection of the info bar at the bottom of images. |
| E1 | What would a naive paper report? | Pretrained backbone, random stratified split (the common setup). |
| E2 | How much is leakage? | Same model, **group-aware split**: images clustered by embedding similarity (threshold chosen on validation), whole clusters assigned to one split. Report the accuracy drop with confidence intervals. |
| E3 | Does the model read the info bar? | (a) train on bar-only crops; (b) train with and without bar removal; (c) Grad-CAM inspection of mistakes. Quantifies shortcut learning. |
| E4 | What helps? | Bar cropping, class weighting, augmentation, temperature scaling (calibration). Selective prediction: abstain below a confidence threshold, report coverage vs accuracy. |

Models: 2 backbones from {ResNet-50, EfficientNetV2-S, ConvNeXt-Tiny}, ImageNet-pretrained, fine-tuned at reduced resolution (about 384 px, cached). Training budget: free GPU tier only.

## 5. Metrics and reporting

- Macro-F1, per-class recall, confusion matrix, expected calibration error (ECE).
- Bootstrap 95% confidence intervals; mean and standard deviation over 3 seeds.
- Every number in the README/report comes from a logged run (config + commit hash). No numbers from memory, and no validation numbers presented as test numbers.
- A "Limitations" section is mandatory: single-lab data, label noise, the group definition is a proxy, no external dataset (unless a compatible one is found).

## 6. Deliverables

1. Public GitHub repo `sem-nanostructure-classifier`: code, tests (data splits, leakage checks, metrics), CI (GitHub Actions), README with results and limitations, MIT license, dataset citation.
2. Report (in README or `REPORT.md`) answering the central question with the E1–E4 numbers.
3. Model card and weights on Hugging Face (small model, with the CC-BY dataset attribution).
4. Small demo (Streamlit): upload an SEM image, get class, calibrated confidence, Grad-CAM, and an "uncertain" state.
5. Portfolio page with no claims beyond measured results, and cross-links to related projects.

## 7. Acceptance criteria

- Splits provably leak-free (a test asserts that no cluster or hash appears in two splits).
- E1 vs E2 comparison present with confidence intervals, including the case where the difference is small (a null result is acceptable and is reported honestly).
- All claims in the README traceable to a logged run.
- CI green; README states the test-set usage rule; no secrets or data files in the repository history.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Group-aware split shows little drop (null result) | Report it; the leakage analysis and the shortcut test remain the contribution. |
| Clustering threshold is arbitrary | Choose on validation; show sensitivity at 3 thresholds. |
| 13.6 GB is heavy for free GPUs | Downscale once, cache, train on the cache. |
| Label noise caps accuracy | Report per-class results and confusion; inspect the worst-confused pairs manually. |
| Scope creep | Anything beyond E0–E4 goes to "Future work". |

Confidence does not separate errors that are shared by near-duplicate images (a cluster of similar images is wrong in the same way and with similar confidence), which is why the intervals are also given by cluster.

Input and preprocessing: same as training and evaluation (`SemDataset`, validation branch): the full image resized to 512 x 384 (no crop of the info bar), ImageNet normalisation, no augmentation; the demo reuses the repository code for this step instead of a second implementation, and a test compares demo output with `evaluate_test` logits for a few stored val images. Output: top-3 classes with the temperature-scaled probability (T = 3.283 of this checkpoint) and the flag "uncertain" when the top confidence is below theta = 0.9150 (E4, fixed on 2026-10-07; not changed after results). Explanation: Grad-CAM of the predicted class, labelled as illustrative and not as evidence of what the model uses (E3 showed only that the bar is not necessary). Security: weights loaded with `torch.load(weights_only=True)` after the sha256 check; uploads (PNG/JPEG, at most 10 MB, at most 4096 x 4096 pixels, decoded with Pillow) are processed in memory only, never written to disk, never logged, and not used for training; no network calls other than serving the page. Honest limits shown in the interface: the model knows only the 10 classes of the NFFA SEM dataset and returns one of them for any image, including non-SEM images (no out-of-distribution detector; low confidence is not a reliable alarm for such inputs); recall is lower in the rare classes (Films_Coated_Surface, Porous_Sponge, Fibres) and the demo rejects them more often (E4); test accuracy of the 3-seed mean and of this seed are reported separately. Example images offered in the demo come from the validation split only, none from train or test. Tests: preprocessing identical to evaluation (stored logits), threshold flag, rejection of oversized or wrongly typed files, no file written during a request.

- 2026-10-07: Scope decision for E4. The ablations "class weights" and "augmentation" of the original E4 plan are not run: the main protocol already reaches macro-F1 0.956, the expected effect on the rare classes (22-46 test images) is below the variation between 3 seeds (about 1 pp), and each variant would need 3 further GPU runs. Bar cropping is covered by E3, temperature scaling and selective prediction by E4a/E4b. The README states that these two ablations were not run. - 2026-10-08: Deployment on Streamlit Community Cloud, specified before implementation. The weights are not in the repository; on first start the app downloads them from the Hugging Face model repository over HTTPS only (no other scheme accepted), into a temporary file next to the target, aborts when more than the expected 111,365,791 bytes arrive, verifies sha256 against `infer.CHECKPOINT_SHA256` and only then renames the file into place; `Classifier.load` verifies the hash again before `torch.load(weights_only=True)`, and a mismatch means no model is loaded. If the target directory is not writable the file goes to the system temporary directory. Uploads stay in memory, nothing is stored or logged (unchanged); no secrets are needed and none are configured. `requirements-demo.txt` is renamed `requirements.txt` (Streamlit Community Cloud reads it from the repository root) and pins CPU-only torch through the PyTorch CPU index, because the default PyPI Linux wheel pulls CUDA libraries. Not verified before deployment: memory use and cold-start time on the free tier; the outcome is recorded here after the first deployment.
